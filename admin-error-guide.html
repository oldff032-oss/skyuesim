📘 Довідник помилок

Що означають записи в логах і що саме робити адміністратору.

Як читати лог

severity: error / warning / info
error — операція не виконана; warning — ризик або тимчасова проблема; info — звичайна подія.
Дія: спочатку перевірте час, email, сторінку, type, message, а потім status і path у context. Не просіть користувача надсилати пароль, PIN, QR або повний ICCID.

Події застосунку

javascript_error
Помилка JavaScript зупинила частину інтерфейсу.
Виправлення: відкрийте вказану сторінку, повторіть дію, перевірте message та назву файлу. Якщо після нового деплою — очистіть кеш/PWA та перевірте синтаксис зміненого скрипту.
promise_rejection
Фонова асинхронна операція завершилася помилкою без обробника.
Виправлення: знайдіть дію перед помилкою; перевірте API та мережу. У коді додайте обробку помилки й зрозуміле повідомлення.
page_view
Не помилка. Користувач відкрив сторінку.
Дія: використовуйте для відновлення послідовності кроків перед збоєм.
connection: offline / online
Пристрій утратив або відновив інтернет.
Виправлення: попросіть перемкнути Wi‑Fi/мобільну мережу та повторити дію після online.

API та HTTP-коди

api_error · 400
Некоректні або неповні дані запиту.
Виправлення: перевірте обов’язкові поля, формат email, суму, код пакета та повідомлення сервера.
401
Сесія відсутня, прострочена або недійсна.
Виправлення: вийти та увійти знову. Для адміна завершити пароль і 2FA. Якщо повторюється одразу — перевірити сховище сесій і системний час сервера.
403
Доступ заборонено роллю, блокуванням або приналежністю даних.
Виправлення: перевірте роль працівника, блокування акаунта та чи призначено йому звернення. Не обходьте перевірку прав.
404
Користувача, тікет, покупку, eSIM або маршрут не знайдено.
Виправлення: перевірте ID/email. Для покупки синхронізуйте Stripe; для старого фронтенду зробіть новий деплой і очистіть кеш.
409
Конфлікт поточного стану: операція вже виконана або бракує передумови.
Виправлення: прочитайте message; оновіть дані користувача, Stripe або eSIM і не повторюйте оплату без перевірки.
410
Push-підписка прострочена або видалена браузером.
Виправлення: користувач/адмін відкриває «Сповіщення» → «Перепідключити» → тест.
429
Забагато запитів або діє захисне обмеження.
Виправлення: зачекати вказаний час; не натискати кнопку багато разів. Перевірити rate limit провайдера.
500
Внутрішня помилка backend.
Виправлення: перевірити Render Logs у той самий час, перший stack trace та змінні середовища.
502
Backend не отримав правильну відповідь від Stripe, eSIM Access або Resend.
Виправлення: перевірити статус/ключі зовнішнього сервісу та точний текст відповіді. Не робити сліпий retry платежу.
503
Функція не налаштована або сервіс тимчасово недоступний.
Виправлення: перевірити Render Environment, VAPID, Resend, Stripe та eSIM API key; після зміни зробити restart.
network_error / Failed to fetch
Браузер не зміг зв’язатися з API: інтернет, CORS, неправильний API_URL або Render спить.
Виправлення: відкрити backend URL, перевірити API_URL у config.js, HTTPS і CORS; потім повторити.

eSIM Access

balance is insufficient
На балансі eSIM Access недостатньо коштів. HTTP 200 тут не означає успіх бізнес-операції.
Виправлення: поповнити баланс провайдера, перевірити ціну пакета і лише потім повторити видачу. Автоматичний retry до поповнення не допоможе.
data plan code ... doesn't exist
Код пакета видалений, неправильний або недоступний.
Виправлення: завантажити актуальний список пакетів eSIM Access і вибрати чинний packageCode. Не вводити код навмання.
top up data plan ... doesn't exist / incompatible
Top-up не існує або несумісний із конкретним ICCID.
Виправлення: запросити сумісні TOPUP-пакети саме для ICCID та вибрати один із повернутих API.
payment_ok_esim_failed
Stripe отримав гроші, але QR/eSIM не видано.
Виправлення: не просити платити повторно. Перевірити покупку; відновити вже створену eSIM або після усунення причини повторити видачу оплаченої покупки. Якщо послугу не надано — refund.
renewal_failed
Щомісячну оплату отримано, але top-up не виконано.
Виправлення: усунути помилку провайдера і використати «Повторити автопоновлення» лише для конкретного invoice.

Stripe та оплати

Webhook signature verification failed
STRIPE_WEBHOOK_SECRET не відповідає webhook endpoint або тіло запиту змінено.
Виправлення: скопіювати signing secret саме активного endpoint у Render; перевірити raw body маршруту; restart.
invoice.payment_failed / renewal_payment_failed
Банк або Stripe не провів автоматичне списання.
Виправлення: користувач оновлює спосіб оплати. Не видавати пакет вручну, доки invoice не стане paid.
resource_missing / payment not found
Stripe ID неправильний, об’єкт видалений або використано інший Stripe-акаунт/режим test-live.
Виправлення: перевірити режим Stripe, ключ, Customer/Charge/Session ID; синхронізувати покупки за email.
receiptEmailError
Покупку збережено, але лист із чеком не надіслано.
Виправлення: перевірити Resend і підтверджений домен. Сам чек залишається у «Історії оплат».

Email, push і 2FA

Resend error 401 / 403
Неправильний API key або відправник/домен не дозволений.
Виправлення: оновити RESEND_API_KEY, підтвердити домен, встановити RESEND_FROM_EMAIL і зробити restart.
onboarding@resend.dev — лист не прийшов
Тестовий відправник може писати лише власнику Resend-акаунта.
Виправлення: підтвердити свій домен у Resend для реальних користувачів.
Push не налаштовано / VAPID
Немає повної пари VAPID ключів або subject.
Виправлення: встановити VAPID_SUBJECT, VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY однієї пари; restart; перепідключити пристрій.
push delivered: 0
Немає активної підписки або браузер її відхилив. Це не гарантує, що користувач побачив повідомлення.
Виправлення: перевірити дозвіл ОС/браузера, встановлення PWA та виконати тест. Критичні повідомлення дублювати email.
TWO_FACTOR_INVALID
Невірний код 2FA; після п’яти спроб challenge видаляється.
Виправлення: запустити вхід заново й використати найновіший лист.
TWO_FACTOR_EXPIRED
Минуло 10 хвилин або код уже використано.
Виправлення: запросити новий код. Перевірити системний час пристрою і сервера.
2FA email not configured
2FA ввімкнено, але backend не може відправити код.
Виправлення: відновити RESEND_API_KEY/домен. Не видаляти дані адміністратора. За потреби Super Admin керує акаунтом після відновлення пошти.

База даних і деплой

database false / persistence error
DATABASE_URL не встановлено або Postgres недоступний; дані можуть не пережити новий деплой.
Виправлення: перевірити DATABASE_URL, доступність Postgres, SSL і Render Logs. Не робити новий деплой до резервної копії, якщо сховище нестабільне.
старий інтерфейс після деплою
Service Worker або Netlify віддає кешовані файли.
Виправлення: перевірити успіх deploy, перезавантажити сторінку, закрити PWA; за потреби очистити дані сайту та встановити PWA знову.
CORS / blocked by origin
Frontend не має дозволу звертатися до backend або використано HTTP замість HTTPS.
Виправлення: перевірити URL Netlify/Render, HTTPS, CORS-конфігурацію та відсутність помилки в config.js.

Коли ескалувати

Негайно зупиніть повторні операції, якщо гроші списані, але послуга не видана; бачите багато 500/502; webhook повторюється; або є підозра на чужий вхід.
Збережіть: час, email, ticket/purchase/invoice ID, точний message і безпечний context. Не копіюйте секрети. Для платежу спочатку звірте Stripe, для eSIM — провайдера, потім обирайте retry або refund.
