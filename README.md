# Сигнал — застосунок глобальної підписки на eSIM

Робочий код (не макет): фронтенд + бекенд. Локально вже зараз можна натиснути
"Оформити підписку" і пройти справжню оплату в **тестовому режимі Stripe**.
eSIM видається через заглушку (mock), поки не підключиш реального провайдера.

## Структура проєкту

```
signal-app/
  backend/          — сервер (Node.js/Express)
    server.js        — головний файл, усі маршрути API
    services/
      stripeService.js  — оплата й підписки
      esimService.js    — видача eSIM (зараз mock, тут підключиш реального провайдера)
    db.js             — проста файлова "база" (data/users.json)
    .env.example       — сюди встав свої ключі
  frontend/          — сайт (звичайний HTML/CSS/JS, без збірки)
    index.html         — головна
    plans.html          — вибір тарифу й оплата
    success.html         — сторінка після оплати
    dashboard.html         — кнопка "Підключити" + статус eSIM
```

## Крок 1 — Запустити локально (з тестовими ключами)

### Постійне зберігання даних у production

Не запускай production лише з локальною папкою `data/`: на Render та схожих
хостингах вона може очищатися після перезапуску. Створи PostgreSQL-базу
(Render Postgres, Neon або Supabase) і додай її connection string у змінну
оточення `DATABASE_URL` бекенду. Під час першого запуску застосунок сам
використає таблицю `app_state` і перенесе до неї наявні JSON-дані.

Без `DATABASE_URL` застосунок працює локально з JSON-файлами, але в логах
буде попередження, що ці дані не є постійними.

1. Зареєструйся на **stripe.com** (безкоштовно). У дашборді Stripe:
   - Ввімкни **Test mode** (перемикач зверху)
   - Developers → API keys → скопіюй **Secret key** (`sk_test_...`)
   - Product catalog → Add product → створи 3 продукти (Базовий $9.99/міс,
     Стандарт $19.99/міс, Безліміт $34.99/міс), тип — **Recurring**.
     Для кожного скопіюй **Price ID** (`price_...`)
   - Developers → Webhooks → Add endpoint → адреса
     `http://localhost:4242/api/webhook` (для локального тесту знадобиться
     Stripe CLI, див. крок 3) → скопіюй **Signing secret** (`whsec_...`)

2. У папці `backend`:
   ```bash
   cp .env.example .env
   ```
   Встав у `.env` скопійовані `sk_test_...`, три `price_...` і `whsec_...`.

3. Встанови залежності й запусти сервер:
   ```bash
   cd backend
   npm install
   npm start
   ```
   Побачиш `Signal backend running on http://localhost:4242`

4. Щоб Stripe міг достукатись до твого локального сервера вебхуком,
   встанови [Stripe CLI](https://docs.stripe.com/stripe-cli) і в окремому терміналі:
   ```bash
   stripe listen --forward-to localhost:4242/api/webhook
   ```
   Він покаже свій `whsec_...` — постав саме його в `.env` замість того, що з дашборду
   (для локальної розробки).

5. Відкрий `frontend/index.html` просто у браузері (або запусти будь-який простий
   сервер, наприклад `npx serve frontend`). Пройди весь шлях: тариф → оплата
   (використай тестову картку Stripe `4242 4242 4242 4242`, будь-яка майбутня дата,
   будь-який CVC) → дашборд → побачиш видану (тестову) eSIM і кнопку "Підключити".

## Крок 2 — Підключити реального eSIM-провайдера

Зареєструйся як партнер в одного з агрегаторів (наприклад eSIM Access,
Airalo Partner API, Monty Mobile — шукай "reseller API" або "partner API"
на їхніх сайтах). Отримаєш `API_URL` і `API_KEY`.

Встав їх у `.env`:
```
ESIM_PROVIDER_API_URL=...
ESIM_PROVIDER_API_KEY=...
```

Відкрий `backend/services/esimService.js` — там уже є готовий шаблон
реального запиту (`fetch(...)`). Тобі треба буде підлаштувати назви полів
під формат саме твого провайдера (це є в їхній документації) — сама
структура коду вже готова.

## Крок 3 — Задеплоїти по-справжньому (щоб працювало не тільки на твоєму компʼютері)

- **Backend**: Render.com, Railway.app або Fly.io — усі мають безкоштовний
  старт, підтримують Node.js "з коробки". Завантаж туди папку `backend`,
  встав змінні з `.env` у їхні "Environment variables".
- **Frontend**: Netlify, Vercel або GitHub Pages — просто завантаж папку
  `frontend`, вона повністю статична.
- Онови `frontend/config.js` — встав туди реальну адресу задеплоєного бекенду
  замість `http://localhost:4242`.
- У Stripe онови webhook endpoint на реальну адресу задеплоєного бекенду.
- Переключи Stripe з Test mode на Live mode (і встав уже `sk_live_...` замість `sk_test_...`).

## Що ще варто зробити перед реальним запуском

- Замінити файлову "базу" (`db.js`) на справжню БД, коли зʼявиться більше
  кількох користувачів (файл не витримає одночасних записів).
- Показувати юзеру Умови використання й Політику конфіденційності
  (обов'язково для збору платежів і email).
- Чітко вказати умови підписки (ціна, періодичність, як скасувати) —
  це юридична вимога в ЄС/США (ясна згода на автопродовження).

## Постійна робота та push-сповіщення

1. У Render відкрий Backend Web Service → **Settings** → **Instance Type** → обери **Starter** (не Free). Free-сервіс засинає через 15 хвилин без запитів.
2. Переконайся, що `DATABASE_URL` веде до постійної PostgreSQL бази. Не використовуй локальні JSON-файли як базу у production.
3. На комп’ютері у теці проєкту виконай `npm install`, потім `npm run generate:vapid`. Збережи обидва рядки: приватний ключ нікому не передавай.
4. У Render → Backend Web Service → **Environment** додай:
   - `VAPID_SUBJECT` = `mailto:твій-email@example.com`
   - `VAPID_PUBLIC_KEY` = значення з команди
   - `VAPID_PRIVATE_KEY` = значення з команди
5. Задеплой нову версію. У застосунку: **Профіль → Сповіщення про трафік → Увімкнути push-сповіщення → Надіслати тестове сповіщення**.
6. Створи в Render **Cron Job** з цього ж GitHub-репозиторію:
   - Command: `node pushWorker.js`
   - Schedule: `0 * * * *` (раз на годину)
   - Додай у нього ті ж `DATABASE_URL`, `VAPID_SUBJECT`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` і ключі eSIM-провайдера, що є у Backend.

На iPhone користувач має додати PWA на початковий екран і натиснути кнопку ввімкнення push власноруч.
