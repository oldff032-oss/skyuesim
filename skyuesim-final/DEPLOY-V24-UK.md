# Signal v24 — безпекове оновлення

## Як розгорнути

1. Завантаж усі файли архіву в GitHub із заміною старих.
2. Переконайся, що файл `data/users.json` видалений із нової версії репозиторію.
3. У Render додай змінні середовища:
   - `ALLOWED_ORIGINS=https://skyesim.netlify.app`
   - `AUTH_CODE_PEPPER=` — випадковий секрет щонайменше 32 символи.
4. Не змінюй наявні Stripe, PostgreSQL, email, eSIM та VAPID-секрети.
5. Дочекайся успішного Render deploy і Netlify deploy.
6. Перевір вхід, тариф, витрати, профіль, підтримку, оплату та адмін-панель.

## Важливо про старі персональні дані

У v24 тестовий `data/users.json` прибрано, але старий файл може залишатися в історії GitHub-комітів. Після успішного деплою зміни або відклич усі секрети, які коли-небудь потрапляли в GitHub. Для повного видалення даних з історії скористайся GitHub Support або `git filter-repo`; перед переписуванням історії обов'язково зроби резервну копію.

## Що перевіряється автоматично

Команда `npm run check` перевіряє синтаксис і запускає безпекові тести. GitHub Actions запускає ці перевірки після кожного завантаження коду. Dependabot щотижня перевіряє оновлення бібліотек.

## Що змінилося

- Дані статусу, трафіку, оплат, скасування та підтримки доступні лише після входу.
- Користувач не може прочитати чуже звернення підміною email або ID.
- Додано постійні обмеження частоти для входу, кодів, відновлення, адмін-входу та оплат.
- Одноразові коди генеруються криптографічно й зберігаються лише як хеш.
- Дозволені вкладення PNG, JPEG, WEBP і PDF до 550 КБ.
- Текст звернень екранується перед показом у застосунку й адмінці.
- CORS обмежено довіреними адресами, додано захисні HTTP-заголовки.
- Email більше не передається в URL після Stripe Checkout.
- Внутрішні помилки сервера більше не показуються користувачу.
# Зміна активного тарифу

- Користувач відкриває **Тарифи → Більше пакетів для подорожей**, обирає пакет і спосіб зміни.
- **Після завершення**: оплата підтверджується зараз, стара Stripe-підписка переводиться в режим без наступного поновлення, а нова eSIM видається в дату завершення.
- **Змінити зараз**: система спочатку створює нову eSIM і лише після успіху скасовує стару Stripe-підписку.
- Адміністратор контролює все на сторінці `admin-plan-changes.html`: заплановані, активні, завершені та невдалі зміни.
- Якщо видача не вдалася, стара eSIM не стирається. В адмінці можна натиснути **Повторити** без нової оплати.

Нові коди діагностики: `CHANGE_MODE_REQUIRED`, `PLAN_CHANGE_ALREADY_PENDING`, `CURRENT_PLAN_END_UNKNOWN`, `SUBSCRIPTION_END_SCHEDULE_FAILED`, `PLAN_CHANGE_PROVISION_FAILED`, `PREVIOUS_SUBSCRIPTION_CANCEL_FAILED`, `ACTIVE_SUBSCRIPTION_EXISTS`.
